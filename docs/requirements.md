# 北冥官网需求文档

版本：0.4

## 项目定位

北冥官网是北冥项目的正式线上门户，也是后续管理后台和服务器运维控制台的统一入口。它不是单纯的展示页，而是要同时承载品牌展示、入服流程、成员档案、社区内容、资源分发、通知消息、运营审核、服务器状态和后台资源管理。

官网面向玩家和访客，后台面向管理员和运维人员。两者可以共享账号体系和权限体系，但页面入口、接口权限、操作审计和风险等级必须分开设计。

## 当前阶段目标

当前后端已经收束为模块化单体，唯一后端 Maven 入口是 `backend/pom.xml`，本地后端端口是 `8135`。后续开发继续按模块补齐契约、测试、实现和验收，不再按仓库内多后端服务入口推进。

本系统需要覆盖官网展示、入服、考试、白名单、内容、素材、考勤、通知、管理后台和服务器运维控制能力。后台资源与服务器管理必须纳入正式范围，包括节点管理、容器管理、虚拟机管理、云盘资源管理、Minecraft 实例管理、日志终端、指标监控和审计回滚。

## 开发范围

本仓库只以当前正式文档为开发依据。开发时不得采用外部实现、临时实验代码或未确认的接口格式。

官网展示、入服审核、白名单、指南、外部交流、论坛、工单、举报、素材、考勤、资源、后台和数据看板都属于本系统正式业务范围。

前端、统一后端入口、认证、资源模块、外部节点执行器对接边界和本地联调脚本都需要按本仓库的正式设计建立。技术栈、接口格式、角色名、数据结构和部署方式必须在进入实现前确认。

账号能力至少覆盖注册、登录、当前用户、退出、会话校验、用户列表和用户修改。最终实现必须兼容 `OWNER`、`ADMIN`、`HELPER`、`USER` 四级基础权限和服务器运维细粒度能力点。

## 核心用户

游客可以浏览公开首页、项目介绍、公告、指南、服务器状态、成员展示、公开社区内容、精彩瞬间和公开资源。

注册用户可以登录、维护个人资料、绑定 Minecraft 身份、参加入服流程、提交白名单申请、参与社区互动、提交工单举报、接收站内通知。

正式成员可以访问成员资源、展示成员档案、提交作品素材、参与活动、查看积分和贡献记录。

协管和审核员可以处理有限范围内的内容审核、素材审核、白名单初审、工单回复、举报初审和玩家协助事项。

管理员可以管理用户、邀请码、内容、指南、资源、社区审核、活动、白名单、考勤、通知、运营配置和数据看板。

超级管理员可以管理角色权限、管理员邀请码、系统配置、备份策略、服务器运维入口、节点密钥和高风险操作授权。

运维人员可以在授权范围内管理服务器节点、容器、虚拟机、云盘资源、Minecraft 实例、文件、日志和运行状态。运维权限不能默认等同于全部业务管理权限。

## 权限等级

系统默认采用 `OWNER`、`ADMIN`、`HELPER`、`USER` 四级基础权限。服务器运维能力在此基础上增加细粒度能力点，例如 `NODE_READ`、`NODE_WRITE`、`CONTAINER_OPERATE`、`VM_OPERATE`、`FILE_MANAGE`、`TERMINAL_ACCESS`、`HIGH_RISK_APPROVE`。

普通用户不能访问后台。协管只能处理被授权的审核和协助任务。管理员不能修改超级管理员身份。超级管理员和被授权运维人员才能执行高风险服务器操作。

## 功能模块

## 官网展示模块

官网首页用于展示北冥项目定位、服务器状态、入服入口、公告资讯、精选内容、成员作品、精彩瞬间、资源下载和常用入口。

首页内容应由后台配置，不能写死在前端。服务器状态异常、资源服务异常或部分接口失败时，页面必须降级展示，不能整页空白。

## 账号、权限与邀请码模块

账号模块负责注册、登录、退出登录、会话校验、密码重置、用户状态、角色权限和 Minecraft 身份绑定。

注册需要支持邀请码。邀请码需要区分玩家邀请码和管理员邀请码，支持有效期、使用次数、禁用状态、绑定角色和使用记录。管理员邀请码只能由超级管理员创建。

密码必须加密存储。登录、注册、密码重置和敏感接口需要频率限制。权限校验必须集中处理，业务模块不能各自实现登录逻辑。

## 成员档案模块

成员档案模块负责成员公开资料、Minecraft ID、UUID、头像、皮肤、成员组、加入时间、成员状态、个人简介、成员事迹、代表作品、活动记录和贡献记录。

成员档案由账号体系、入服审核和管理员维护共同驱动。其他模块可以保存成员快照字段，但主数据归成员档案模块维护。

## 入服引导、考试与白名单模块

系统需要支持新玩家从注册到入服的完整流程，包括邀请码注册、绑定 Minecraft ID、阅读规则、选择审核方向、参加考试、提交白名单申请、等待审核和审核结果通知。

考试方向包括红石、后期、建筑和通用方向。考试支持单选、多选、判断、简答题，客观题自动判分，简答题人工审核。

白名单审核支持通过、拒绝、要求补充和备注。审核通过后创建或激活成员档案，并初始化考勤积分。被移除白名单后重新入服需要进入二次考核，二次考核难度应高于上次。

## 指南与知识库模块

指南模块负责服规中心、进服指南、游玩指南、玩家指南、工程说明、活动说明、常用指令、客户端下载、Java 环境说明、服务器地址查询和下载加速说明。

指南内容需要支持分类、标签、搜索、目录、置顶、版本记录和后台维护。北冥云盘、整合包下载、服务器地址、MCS 指令说明和插件指南都归入指南与知识库模块维护。

## 服务器状态与线路模块

服务器状态模块负责展示 Minecraft 服务器在线状态、版本、MOTD、在线人数、最大人数、延迟、线路状态、历史峰值、宕机记录和开服时长。

它只负责面向玩家的状态展示和线路查询，不负责后台运维控制。容器启停、虚拟机管理、节点文件操作和终端命令属于服务器运维控制模块。

## 外部交流入口模块

系统需要展示 Oopz、QQ群、游戏内聊天等外部交流入口，说明每个渠道的用途、加入条件、规则和注意事项。

官网不替代即时聊天工具，不同步外部聊天记录，不做跨平台 SSO。正式申请、申诉、举报、审核和运营记录以官网系统为准。

## 社区、工单、举报与处罚模块

社区模块负责板块、帖子、评论、点赞、收藏、投票、举报和审核。论坛用于沉淀教程、建议、作品展示和公告讨论，不替代即时聊天。

工单用于处理封禁申诉、白名单问题、账号问题、资源问题、BUG 反馈和素材争议。举报用于处理帖子评论违规、游戏内违规、素材侵权和冒名顶替。

处罚记录需要支持警告、禁言、封禁、移除白名单、限制投稿和限制发帖，并保留处理人、处理时间、证据、原因和状态变化。

## 通知模块

通知模块负责站内通知、未读数、已读状态、通知归档、模板配置和通知渠道预留。

考试结果、白名单审核、素材审核、工单回复、积分变化、处罚结果、服务器维护和后台高风险操作都可以触发通知。

## 内容、素材与精彩瞬间模块

内容模块负责公告、文章、页面内容、摄影作品、成员作品、服务器进度、成就、里程碑和专题页。

素材模块负责玩家投稿、文件上传、素材授权、审核、精选、下架和归档。上传文件需要限制类型、大小、数量和频率，危险脚本和可执行文件不得直接公开访问。

精彩瞬间模块负责截图、视频、活动记录、纪念合影、建筑完成时刻和高光内容展示。

## 活动、投票、日历与更新日志模块

活动模块负责活动发布、报名、参与名单、结果、获奖名单、奖励记录和贡献加分。

投票模块负责成员投票、选项、投票资格、投票记录、结果统计和归档。投票可以用于活动决策、服务器规则调整、工程事项和社区治理。

日历模块负责活动时间、维护时间、工程节点、投票截止、版本更新时间和服务器日程。

更新日志模块负责服务器版本、插件变更、规则调整、资源包更新、地图更新和重要维护记录。

## 资源与云盘模块

资源模块负责客户端整合包、材质包、光影包、地图文件、规则文档、活动资源、下载链接、版本记录、下载权限和资源可见范围。

第一阶段可以使用 Cloudreve 分享链接作为资源入口。后续如果接入 Cloudreve API，需要支持资源目录同步、分享链接生成、下载权限校验、文件元数据同步和资源失效降级。

玩家可见的资源下载和后台运维里的文件管理不是同一个权限域。前者面向内容分发，后者面向服务器运维。

## 活跃度、贡献考勤与榜单模块

考勤模块负责成员活跃度、工程贡献、活动参与、作品提交、协助管理、积分流水、榜单和每月扣分任务。

成员通过入服审核后初始化考勤积分。连续一个月没有上线、没有参与工程、没有参与活动时扣分。积分小于等于 0 后进入待移除白名单流程，必须由管理员确认后执行。

所有积分变化必须有流水。自动任务必须有周期标识，避免重复扣分。

## 管理后台模块

管理后台提供统一入口，但不能吞掉所有业务职责。它负责聚合待办、配置页面、审核队列、数据看板、操作日志和系统配置，具体业务规则仍归属对应模块。

后台需要覆盖用户管理、邀请码管理、内容管理、指南管理、素材审核、工单处理、举报处罚、白名单审核、考勤管理、资源管理、活动管理、通知模板、SEO 配置、外部交流入口、服务器线路配置和在线地图接口预留。

## 服务器与资源运维管理模块

服务器与资源运维管理模块是后台核心能力。它面向管理员和运维人员，用来管理真实服务器资源，不面向普通玩家开放。

该模块需要维护资源资产清单，包括物理服务器、云服务器、LXC 容器、Docker 容器、虚拟机、Minecraft 实例、反向代理服务、Cloudreve 服务、数据盘、备份盘、线路和域名。

系统需要支持节点接入。每台被管理服务器后续部署独立外部节点执行器，由控制台进行注册、认证、心跳、版本检查和能力上报。节点断线或外部执行器未连接时，后台显示离线状态，并禁止执行需要实时连接的操作。

容器管理需要支持查看容器列表、状态、镜像、端口、卷挂载、环境变量、资源占用、启动、停止、重启、删除、日志查看和指标采集。镜像管理需要支持镜像搜索、拉取、版本选择和拉取进度展示。

虚拟机管理需要支持查看虚拟机列表、运行状态、CPU、内存、磁盘、网络、启动、关机、重启、强制停止、快照和控制台入口。具体能力取决于底层虚拟化平台，第一阶段可以先定义接口和模拟数据。

Minecraft 实例管理需要支持实例列表、运行状态、在线人数、版本、目录、启动命令、日志、控制台命令、启动、停止、重启和配置文件入口。对接 MCSManager 或独立外部节点执行器时，要保留适配层。

文件管理需要支持在授权目录内浏览、上传、下载、重命名、移动、删除、编辑文本配置和查看文件大小。文件操作必须限制根目录，禁止路径穿越，危险操作必须记录审计。

终端和日志能力需要支持实时日志流、命令执行、WebSocket 通道和操作超时。终端权限必须单独授权，不能因为拥有后台登录权限就默认允许执行命令。

监控能力需要支持节点 CPU、内存、磁盘、网络、负载、进程、容器资源、Minecraft 实例状态和最近异常事件。第一阶段可以先做实时状态和历史快照，后续再做告警规则。

高风险操作包括删除容器、删除文件、重启核心服务、强制停止实例、执行终端命令、修改节点密钥、修改反向代理、修改数据盘挂载、恢复备份和删除备份。这些操作需要二次确认、权限校验、审计日志，必要时需要超级管理员审批。

## 通用状态与流程要求

内容、素材、指南、帖子、工单、举报、白名单、活动和资源都需要统一状态模型。默认状态包括草稿、待审核、已通过、已拒绝、需修改、已下架和已归档。

审核流程必须记录提交人、审核人、审核时间、审核意见、状态变化和通知结果。需要玩家补充材料的流程，必须能返回到提交人继续编辑。

删除类操作优先采用软删除或归档。真实删除只允许在权限、审计和备份策略都满足时执行。

每个模块开始开发前，必须写清楚接口、数据归属、权限、状态流转、失败降级和验收口径。没有验收口径的模块不能进入实现。

## 非功能需求

系统必须有统一响应格式、统一错误码、统一分页格式和统一认证方式。

所有后台接口必须做权限校验。所有管理员关键操作必须记录审计日志。高风险操作必须记录操作者、目标对象、操作原因、请求参数摘要、操作前状态、操作后状态、执行结果和失败原因。

业务模块不能直接读取其他模块数据库。跨模块通信必须通过明确接口。高频展示字段可以保存快照，但快照不是主数据。

上传文件、云盘资源、节点密钥、数据库连接、第三方 token 和运维凭证不能明文提交到仓库。

系统需要支持备份与恢复策略。至少要覆盖数据库、上传素材、资源元数据、邀请码、白名单、考勤积分、处罚记录、审核记录、节点配置和运维审计记录。

## 阶段优先级

P0 阶段先完成正式文档、基础工程结构、账号权限、成员档案、官网内容、服务器状态、资源展示、通知基础能力和管理后台骨架。

P1 阶段完成入服引导、考试、白名单、素材审核、工单举报、考勤积分、社区基础能力、活动日历、更新日志和 Cloudreve 分享链接资源入口。

P2 阶段完成服务器与资源运维管理模块的控制面、外部节点执行器对接、容器管理、Minecraft 实例管理、日志流、文件管理和审计闭环。

P3 阶段再扩展虚拟机管理、Cloudreve API 深度接入、自动告警、备份恢复、镜像市场、在线地图对接、插件联动和跨平台通知。

## 待确认问题

后台资源与服务器运维模块最终由同伴的 Go 节点执行器接入，还是由独立外部项目实现节点协议，需要在开发该模块前确认；官网后端仓库不直接实现节点执行器。

Cloudreve 第一阶段只使用分享链接，还是同步目录和权限，需要在资源模块开发前确认。

Minecraft 实例管理是优先对接 MCSManager，还是优先走独立外部节点执行器，需要在运维模块开发前确认。

虚拟机管理使用哪种底层平台，例如 Proxmox、LXD、Docker/LXC 或云厂商 API，需要在 P2 或 P3 开始前确认。
