# 北冥官网 auth 测试台测试文档

版本：0.1

## 文档定位

本文档是 `frontend/auth-test-console` 的正式测试文档。该前端只作为 auth 微服务本地联调工具，不承担正式业务前端职责。测试台必须以 `docs/contracts-auth.md` 和 `docs/tests-auth.md` 为接口行为来源，只调用 auth 已有 API，不新增业务规则。

## 测试目标

测试台必须能让开发者在浏览器里完成 auth 核心接口联调。页面中的导航、表单、按钮、响应面板和错误状态都必须有可验证行为，不能只展示静态样式。所有测试用例通过后，才允许认为测试台可用于 auth 本地测试。

## 启动约束

测试台默认通过 Vite 在 `127.0.0.1` 启动，允许端口为 `5173`、`5174` 或 `5182`。auth 后端固定为 `http://localhost:8101`。当后端未启动时，页面必须能正常渲染并显示离线或请求失败状态，不能整页崩溃。浏览器测试应优先复用本机 Microsoft Edge，不要求下载浏览器。

| AUTH-UI-015 | 禁用邀请码 | 点击邀请码列表中的禁用按钮 | 对应邀请码状态变为 `DISABLED`，最近事件显示成功响应。 |
| AUTH-UI-016 | 注册表单 | 使用可用玩家邀请码提交注册 | 返回会话，当前用户切换为新注册用户。 |

| AUTH-UI-018 | 退出登录 | 登录后点击 `退出` | token 清空，当前用户回到未登录状态，受保护按钮不可继续提交。 |
| AUTH-UI-019 | 错误响应展示 | 输入错误密码或无权限操作 | 最近事件展示统一错误响应，不吞掉错误码和 message。 |
| AUTH-UI-020 | 构建验证 | 执行前端构建 | TypeScript 和 Vite 构建成功，无类型错误。 |
| AUTH-UI-021 | 后端契约回归 | 执行 auth 后端测试 | `docs/tests-auth.md` 对应自动化测试全部通过。 |

## 验收口径

`AUTH-UI-001` 到 `AUTH-UI-021` 必须都有自动化或可复现验证。顶部导航按钮必须是真实交互，点击后要改变当前选中状态并移动到对应区域。所有接口按钮必须在后端可用时调用真实 auth API，在后端不可用时显示明确失败响应。测试通过不能依赖手工刷新、浏览器缓存或隐藏的旧 token。

## 测试过程记录

### 2026-05-21 顶部导航无响应缺陷闭环

测试范围：`frontend/auth-test-console` 顶部导航、页面分区定位、auth 接口按钮、邀请码操作、前端构建和 auth 后端契约回归。测试环境为 Windows 本地仓库，测试台通过 Vite 在 `127.0.0.1:5174` 运行，浏览器自动化复用本机 Microsoft Edge，auth 后端使用 `http://localhost:8101`。

首次失败验证：先新增本文档用例和 `frontend/auth-test-console/tests/e2e-auth-console.mjs`，执行 `npm run test:e2e`。结果失败，失败位置为顶部导航点击后的 `aria-current='page'` 等待超时。失败原因是顶部 `概览`、`账号`、`会话`、`邀请码`、`日志` 按钮只有静态 UI，没有绑定点击处理、当前选中状态或滚动定位行为。该失败覆盖 `AUTH-UI-002` 到 `AUTH-UI-006`。

第一次修复：为顶部导航增加分区 refs、当前选中状态和 `scrollIntoView` 行为；为 `北冥认证器` 补充可被测试定位的标题；把账号操作容器调整为语义化 section。复测 `npm run test:e2e` 时出现两个测试实现问题：`会话` 按钮选择器同时匹配了 `会话校验`，TypeScript 构建发现账号区 ref 类型与 `div` 不匹配。修复方式是把测试选择器限定在 `aria-label="测试台导航"` 的导航区域内，并将账号区容器改为 `section`。

第二次验证：执行 `npm run test:e2e`，结果通过。执行 `npm run build`，结果通过，TypeScript 和 Vite 构建无错误。该轮确认 `AUTH-UI-001` 到 `AUTH-UI-007` 的主要交互和构建基础可用。

完整联调扩展：将 E2E 增加 `--with-backend` 模式，覆盖快速登录、当前用户、会话校验、用户列表、邀请码列表、创建邀请码、禁用邀请码和退出。首次执行 `npm run test:e2e:full` 失败在用户列表断言，原因是测试错误地假设第一页一定包含 `owner`，但后端排序下第一页包含 `admin`、`user` 等种子用户。修复为断言分页 `items` 存在并包含稳定种子用户 `admin`。再次执行时失败在 `邀请码` 按钮选择器，原因是顶部导航和快捷操作区有同名按钮。修复为限定 `.quick-actions` 区域内的 `邀请码` 按钮。再次执行时失败在禁用邀请码，原因是连续测试后列表首项可能已经是 `DISABLED`，按钮不可点击。修复为选择第一个未禁用的 `.icon-action:not([disabled])`。

反复复测结果：执行 `npm run test:e2e:full`，结果通过；执行 `mvn test`，结果为 43 个测试全部通过，失败 0，错误 0，跳过 0；执行 `npm run build`，结果通过；再次执行 `npm run test:e2e:full`，结果通过；再次执行 `mvn test`，结果仍为 43 个测试全部通过，失败 0，错误 0，跳过 0。该轮覆盖 `AUTH-UI-001` 到 `AUTH-UI-015`、`AUTH-UI-018`、`AUTH-UI-020` 和 `AUTH-UI-021`。`AUTH-UI-016`、`AUTH-UI-017`、`AUTH-UI-019` 已在测试文档列为验收用例，后续扩展测试台时需要继续补足自动化断言。

结论：本轮修复确认顶部导航不再是静态按钮，点击后会切换选中状态并定位到对应区域；auth 核心联调按钮可在完整 E2E 中调用真实后端；重复执行暴露出的不稳定断言已修正。剩余风险是注册表单、Minecraft 绑定和错误响应展示尚未加入本轮完整 E2E 的自动化断言，需要在下一次测试台增强时补齐。
